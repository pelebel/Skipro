# SkiPro Fix Plan

## Scope

This plan addresses all 20 issues identified in the code review, ordered by priority. Each fix is scoped to minimal, safe changes.

---

## Phase 1: Critical Bugs

### Fix #1: HTML i18n Typo (`index.html:30`)
- Remove the malformed `data-i1 idea="realtime"` attribute from the span element.

### Fix #2: Conflicting Inline `display` Styles (`index.html:33`)
- Remove the redundant `display: none;` from `#liveScoreContainer`'s inline style. The later `display: flex;` already overrides it, and JS sets it explicitly on line 303 anyway.

### Fix #3: Negative Score Floor (`script.js:221`)
- Change `score: Math.min(finalScore, 100)` to `score: Math.min(Math.max(finalScore, 0), 100)` so scores clamp to `[0, 100]`.

### Fix #4: Hourly Data Bounds Guard (`script.js:320-325`)
- Add a length check before passing `hourlyData` to `calculateProScore`:
  ```javascript
  if (hourlyData.temps.length < 24) {
      hourlyData.temps.length = 24; // pad or skip
  }
  ```
- In `calculateProScore`, add a bounds check in the Prime Window loop to avoid reading `undefined` from short arrays.

---

## Phase 2: Security

### Fix #5: URL Encode User Input (`script.js:254`)
- Wrap `city` with `encodeURIComponent(city)` in the geocoding fetch URL.

### Fix #6: Replace `innerHTML` with Safe DOM Construction (`script.js:365-378`)
- Replace the `card.innerHTML = ...` template literal in `renderCard()` with `document.createElement` + `textContent` calls. This eliminates the XSS vector and is more performant (no HTML parsing).

---

## Phase 3: Accurate Scoring

### Fix #12: Fetch Current Humidity from API (`script.js:280`)
- Add `relative_humidity_2m` to the `current=` API parameter.
- Use the fetched value instead of the hardcoded `50` in the live score calculation.

---

## Phase 4: Code Quality

### Fix #9: Remove Dead Code (`script.js:126-129`)
- Delete the `toggleUnits()` function entirely.

### Fix #10: Replace `alert()` with `showError()` (`script.js:236-239`)
- Replace both `alert()` calls in `autoLocate()` with `showError(...)` to use the existing in-UI error display.

### Fix #8: Remove Inline Event Handlers (`index.html:19,46`)
- Remove `onsubmit` from `<form>` and `onclick` from the "Use My Location" button.
- Add `addEventListener` calls in `script.js` during `window.onload`.

### Fix #7: Namespace Encapsulation
- Wrap all JS logic in an IIFE to avoid polluting the global scope.
- Only the functions called from the new `addEventListener` handlers need to be referenced, which the IIFE closure handles naturally.

---

## Phase 5: Performance

### Fix #13: Add Request Cancellation with `AbortController`
- Store an `AbortController` reference in `state`.
- Before each fetch, abort the previous controller.
- Pass `signal` to both the geocoding and weather fetch calls.
- Catch `AbortError` and ignore it silently.

### Fix #14: Cache `Intl.DateTimeFormat` Formatters
- Create formatters once in `window.onload` and reuse them in `renderCard()`.

---

## Phase 6: Accessibility

### Fix #15: Add `aria-live` Regions
- Add `aria-live="polite"` to `#weatherDisplay`.
- Add `role="alert"` to `#errorMsg` (it already has `class="error"`).

### Fix #16: Make Spinner Accessible
- Add `role="status"` and `aria-label="Loading"` to `#loadingSpinner`.
- Make it visible to screen readers when loading starts (currently `display: none` hides it from AT).

### Fix #17: Contrast Check
- The yellow scores (`#ccff00`, `#ffdf00`) on the dark glass background likely pass WCAG AA for large text (the score numbers are 1.2rem+). No code change needed, but document this in a comment.

---

## Phase 7: Minor

### Fix #18: Clean Up Trailing Spaces in HTML Tags
- Fix `</div >` → `</div>` on lines 39, 42, 49.

### Fix #19: Add Meta Description
- Add `<meta name="description" content="Real-time ski condition scoring for mountains worldwide.">` in `<head>`.

### Fix #20: Add Favicon Placeholder
- Add `<link rel="icon" href="data:,">` to prevent 404 requests (empty favicon as placeholder until a real one is designed).

### Fix #11: Update `CLAUDE.md`
- Remove the line "Supports both Celsius and Fahrenheit" since only Celsius is implemented.
